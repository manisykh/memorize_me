# Memorize Me 실제 기기 시각 디자인 평가

작성: 2026-09-07 · 캡처: 2026-09-05 및 09-07, 동일 감사 작업의 연속 세션

## 결론

현재 디자인은 **차분한 녹색·크림색, 큰 조작 영역, 읽기 쉬운 콘텐츠**라는 좋은 기반이 있다. 다만 여러 화면에서 **설명과 통계가 실제 행동보다 크게 배치되고, 카드·배지·굵은 글자가 반복되어 중요도 차이가 약하다.** 상용 앱 수준의 마감에 가장 필요한 것은 장식 추가보다 화면별 강조 순서와 공간 배분을 다듬는 일이다.

실기기에서 확인한 가장 시급한 문제는 단어장 플랜 설명과 퍼센트의 충돌, 학습 콘텐츠보다 큰 안내 패널, 사용자 단어장을 아래로 밀어내는 기본 자료 목록이다. 화면별 근거와 수정 기준을 아래에 제시한다. 주관적인 완성도 점수나 전환율 상승 수치는 부여하지 않았다.

## 검토 환경과 범위

- 도구: 사용자 요청에 따른 ADB 화면 이동, screencap, UI Automator 접근성 트리 확인. Product Design audit 방식으로 실제 캡처에 근거해 평가했다.
- 기기: SM-S906N, 화면 1080×2340, density override 420dpi(약 411dp 폭).
- 환경: 밝은 테마, 글자 배율 1.15, font weight adjustment 300. 09-05 확인 시 bold_text=1이었다. 09-07에도 배율과 굵기 보정 값이 유지됨을 확인했다.
- 따라서 이 보고서의 글자·줄바꿈 평가는 **사용자의 확대·굵게 표시 환경**에 대한 것이다. 기본 글자 설정에서도 동일하게 보인다고 주장하지 않는다. 기기 설정은 변경하지 않았다.
- 설치 앱: com.memorize.me, versionName 1.0.0 / versionCode 1, lastUpdateTime 2026-09-03 21:47:29. 현재 작업 디렉터리 소스와 동일 빌드라는 검증은 하지 않았다. 이번 시각 증거는 설치 앱 기준이다.
- 원본 캡처를 편집하지 않고 저장·열람했다. 폴더명은 감사 시작일을 유지했다. 중간 화면 확인용 파일은 보존하되 아래에는 대표 증거 15장을 선정했다.
- 새 단어 카드 앞/뒤와 퀴즈 선택 상태까지 확인했다. 알아요/몰라요 판정이나 정답 제출은 하지 않았다. 학습 완료·결과·저장 실패 상태는 미검증이다. 세션 진입에 따른 시작 이벤트가 발생했을 수 있다.
- AI 요청, 단어장 추가·삭제·편집 저장, 계정 변경을 실행하지 않았다. 마지막에는 홈으로 돌아왔다.
- 모든 테마, 오류·빈 단어장, 긴 퀴즈 선택지, 스크린리더 실제 읽기, 모션 감소는 추가 검증이 필요하다. screenshot으로 전체 접근성 준수나 성능을 확정하지 않는다.

## 1. 홈 — 명확한 시작 버튼을 살리고 반복 안내를 줄인다

![1. 홈](C:/Users/manis/flutter_PJT/memorize_app/design_audit_2026-09-05/21-home-final.png)

**잘된 점:** 가장 진한 녹색 버튼이 시작 행동을 잘 드러낸다. 복습·새 단어·학습 중 구분은 숫자와 문구를 함께 사용한다. 활성 탭도 색과 선택 배경으로 구분된다.

**문제:** `새 단어 12개 시작`이 카드 제목과 버튼에 반복되고, 버튼 설명에서도 `새 단어 12개부터 시작`을 다시 쓴다. 남은 12개는 제목 아래·KPI·진행 영역에서 다시 나타난다. 정보량에 비해 큰 패널을 사용해 아래 단어장 상태는 첫 화면에서 일부만 보인다. 스크롤되는 콘텐츠가 하단에 걸쳐 보이는 것 자체는 잘림 버그가 아니다.

**수정 방향:** 제목은 `오늘의 학습`, 버튼은 `새 단어 12개 시작`, 보조 정보는 범위나 예상 시간처럼 새로운 정보만 제공한다. 오늘 진행은 한 줄과 얇은 진행 막대로 묶고 장기 기억 분포는 상세로 보낸다. 전체 헤더의 브랜드와 범위 표시를 간결하게 하되 단어장 전환 가능성은 드롭다운 표시로 명확히 한다.

**접근성:** 도움말 아이콘의 접근성 bounds는 약 74px, 현재 배율 기준 약 28dp다. 실제 터치 확장 여부는 별도 확인해야 하지만 확대된 사용자 환경에서도 누르기 쉬운 타깃으로 보완할 필요가 있다.

**우선순위/검증:** P1. 오늘의 대상·수량·시작 행동을 중복 설명 없이 식별할 수 있는지 확인한다. 터치 목표 검증은 [Flutter 접근성 가이드](https://docs.flutter.dev/ui/accessibility)의 기준을 활용한다.

## 2. 복습 — ‘아직 안 했음’보다 ‘지금 시작’을 먼저

![2. 복습](C:/Users/manis/flutter_PJT/memorize_app/design_audit_2026-09-05/10-resume.png)

**잘된 점:** 카드·객관식·스펠링의 기록을 같은 형태로 비교할 수 있다. 시작 카드에는 화살표가 있어 이동 가능성이 드러난다.

**문제:** 이 단어장은 완료 이력이 없는데 `아직 완료한 학습 없음 / 0회` 세 줄이 매우 큰 카드에 반복된다. 캡처상 y=552~1457, 약 905px를 이 영역에 사용하며 첫 학습 카드가 y=1662에서 시작한다. 셀프 테스트는 하단에 일부만 보인다. 설명의 `올립니다`도 줄 끝에서 분리되어 읽기 흐름이 끊긴다.

**수정 방향:** 이력 없음은 `첫 학습을 시작해보세요` 한 줄로 축약하고 카드·퀴즈 진입을 상단에 둔다. 이력이 생긴 뒤에는 최근 기록만 접힌 요약으로 표시한다. 보조 문장은 짧게 쓰고 자연스러운 줄바꿈을 검증한다.

**접근성:** 시스템 굵게 표시 환경에서도 제목·설명의 구분이 유지되도록 크기·간격·위치로 위계를 만든다. 굵게 표시 설정을 끄도록 요구하는 해결책은 적절하지 않다.

**우선순위/검증:** P1. 학습 기록이 없는 단어장에서도 첫 화면에 카드와 테스트 진입이 완전히 보이도록 개선한다.

## 3. 통계 — 큰 0%보다 의미 있는 설명

![3. 통계](C:/Users/manis/flutter_PJT/memorize_app/design_audit_2026-09-05/03-stats.png)

**잘된 점:** 0%·12개·0개 수치가 분리되어 읽힌다. 여백 자체는 깨끗하다.

**문제:** 첫 학습 전 상태에서는 원형 0%와 전체/안정 기억 숫자 외에 얻는 정보가 적고, 하단이 크게 비어 있다. `전체 단어장 · 현재 학습 기준 · Lesson4_Voca4 전체`라는 문구는 전체 계정의 합계인지 현재 단어장인지 혼란스럽다. 실제 집계 오류라고 확정하지는 않는다.

**수정 방향:** 범위를 `Lesson4_Voca4 전체`처럼 하나로 명시한다. 최초 상태에는 `아직 학습 전이에요`와 첫 학습 행동을 제공하고, 기록이 있는 경우 주간 학습량·최근 변화·다음 복습을 제공한다. 빈 공간을 장식용 그래프로 채우지는 않는다.

**접근성/한계:** UI 트리에 차트 관련 100과 0이 별도 노출된다. 실제 낭독 순서와 차트 요약 문장을 확인해야 한다. 데이터가 있는 통계 화면은 미검증이다.

**우선순위/검증:** P2. 사용자가 수치의 범위와 다음 행동을 설명할 수 있어야 한다.

## 4. 달력 — 선택과 빈 상태를 다듬는다

![4. 달력](C:/Users/manis/flutter_PJT/memorize_app/design_audit_2026-09-05/04-calendar.png)

**잘된 점:** 월 이동·오늘·현재/전체 단어장 선택이 분명하다. 날짜 칸에 선택 배경과 테두리가 있으며 UI 트리에 날짜·선택 상태가 포함된다.

**문제:** 비어 있는 달력에서도 카드·객관식·주관식·SRS·플랜의 범례 5개가 항상 표시된다. 아래에는 완료 없음과 일정 없음이 각각 반복된다. 선택일은 밝은 민트 사각형이고 다른 화면의 선택은 옅은 녹색 pill이어서 공통 선택 규칙이 약하다.

**수정 방향:** 빈 달에는 핵심 설명 하나와 학습 이동을 제공한다. 범례는 실제 있는 기록을 중심으로 설명하거나 상세에 둔다. 선택일과 오늘의 표시를 구분하고 브랜드 선택 색을 정리한다.

**접근성/한계:** 날짜의 실제 스크린리더 조작은 미검증이다. 기록이 많은 날과 여러 유형이 겹친 상태도 별도 확인해야 한다.

**우선순위/검증:** P2. 오늘·선택일·기록일을 색 없이도 구분하고 빈 상태에서 다음 행동을 찾을 수 있어야 한다.

## 5. AI 학습 — 준비가 끝났으면 생성이 주인공

![5. AI 학습](C:/Users/manis/flutter_PJT/memorize_app/design_audit_2026-09-05/05-ai.png)

**잘된 점:** 생성 준비 완료와 외부 전송 안내가 명시되어 있다. 예문·퀴즈·문법을 서로 다른 목적의 카드로 구분했다.

**문제:** 이미 준비 완료 상태인데 첫 큰 버튼이 `설정 탭에서 AI 설정 관리`다. 설정 카드와 베타 안내가 y=557~1261을 차지하고 첫 생성 기능은 y=1308에 나온다. 주의 설명에는 단어 중간 줄바꿈도 있다.

**수정 방향:** 준비 상태는 작은 상태 라벨과 `변경` 링크로 압축한다. 생성 기능을 위로 올린다. 외부 전송과 검토 필요성은 숨기지 않되 간단한 안내와 상세 보기, 실행 시 필요한 안내로 구성한다.

**접근성/한계:** 현재 키가 등록된 상태만 확인했다. 미등록·실패·생성 중·결과 화면은 미검증이고 외부 AI 요청은 실행하지 않았다.

**우선순위/검증:** P1. 준비된 사용자는 기능 선택을 먼저 보고, 설정을 찾는 사용자도 명확히 접근할 수 있어야 한다.

## 6. 설정 — 그룹은 유지하고 설명을 짧게

![6. 설정](C:/Users/manis/flutter_PJT/memorize_app/design_audit_2026-09-05/06-settings.png)

**잘된 점:** 관련 설정의 그룹과 펼치기 화살표가 명확하다. 접힌 초기 상태로 상세 설정량을 조절했다.

**문제:** 보조 설명까지 굵고 여러 줄이라 각 그룹이 크게 보인다. `클 / 라우드`, `선택 / 합니다` 같은 줄바꿈이 생긴다. 모든 항목에 테두리·배경·큰 아이콘을 사용해 목록을 빠르게 훑기 어렵다.

**수정 방향:** 접힌 상태는 `테마 · 밝음`, `음성 및 효과음`처럼 현재 값이나 핵심 대상만 표시하고 자세한 설명은 펼친 뒤 제공한다. 설정 목록은 비교적 평평한 행으로, 중요한 구역만 카드로 강조한다.

**접근성/한계:** 기본 폰트가 아닌 확대·굵게 표시 조건의 관찰이다. 계정·API 세부 내용은 열지 않았다.

**우선순위/검증:** P2. 현재 환경에서 단어가 어색하게 잘리지 않고 원하는 그룹을 빠르게 찾게 한다.

**잘된 점:** 단어/뜻 구분, 탭해서 뒤집기 안내, 발음/한글 뜻 버튼이 명확하다. 카드 중앙 탭으로 실제 뜻 면으로 전환되는 것을 확인했다. 알아요·몰라요는 아이콘·문자·색을 함께 사용한다.

**문제:** 상단에 새 단어 제목·SRS 설명·진행 막대·3개 지표 카드가 겹친다. `진행 0/12`와 `남음 12개`는 같은 상태를 반복하며 `단계 진입`은 행동에 도움이 적다. 중앙 단어의 시각적 크기는 주변 제목·조작부에 비해 두드러지지 않는다. 큰 그림자와 여러 컨테이너가 단어보다 화면 틀을 강조한다. 하단 판단 버튼 영역은 화면 끝에 가까워 여유가 적다.

**수정 방향:** 상단은 단어장·진행 한 줄·얇은 막대로 줄인다. 단어와 뜻은 학습의 주인공으로 강조하고, 카드 그림자는 단어 카드 한 곳에만 약하게 둔다. `이번 학습 기록`보다 `몰라요 / 알아요` 행동 라벨이 먼저 읽히게 한다. 발음은 충분한 터치 영역을 유지하며 보조 행동으로 조정한다.

**접근성 위험:** 앞면 캡처의 UI 트리에서 현재 단어 외에 다음 카드 단어와 뜻도 focusable 노드로 존재한다. 보이지 않는 카드가 낭독 대상이 될 가능성이 있다. 현재 카드만 semantics에 남기는 처리가 필요한지 TalkBack으로 검증해야 한다. 실제 낭독이 발생했다고 주장하지 않는다.

**우선순위/검증:** P1. 단어가 가장 먼저 눈에 들어오고 현재 카드만 읽히며, 큰 글자에서 판단 버튼이 시스템 제스처 영역과 충분히 분리되어야 한다. 음성 재생·카드 판정·되돌리기·완료 결과는 미실행이다.

## 9. 테스트 허브 — 안내를 거치지 않고 방식을 고르게

![9. 테스트 허브](C:/Users/manis/flutter_PJT/memorize_app/design_audit_2026-09-05/11-quiz-hub.png)

**잘된 점:** 단어장 선택과 문제 수, 비활성 오답 상태가 분명하다. 각 방식이 독립적으로 구분된다.

**문제:** 단어장 선택과 `오늘의 테스트 루틴` 패널이 화면 상단 상당 부분을 차지한다. 객관식 시작은 카드 안 작은 pill처럼 보이지만 전체 카드가 클릭 가능하다. 설명도 길어 행동 찾기에 불필요한 읽기 부담이 생긴다.

**수정 방향:** 단어장/범위는 짧은 선택 행으로, 객관식·스펠링은 간결한 실행 목록으로 만든다. 카드 전체가 버튼이면 화살표·일관된 선택 피드백으로 표현하고 장식형 버튼을 안에 중복하지 않는다. 오답 0개 상태는 작은 상태 설명으로 낮춘다.

**접근성/한계:** 비활성 오답은 흐리게만 보이지 않도록 이유 문구를 유지한다. 시험지 설정은 이번 대표 화면 범위에 포함하지 않았다.

**우선순위/검증:** P1. 첫 화면에서 두 학습 방식과 문제 수, 시작 행동을 바로 비교한다.

## 10~11. 객관식 — 문제와 선택지 중심으로 위계를 재배치

| 10. 선택 전 | 11. 선택 후, 제출 전 |
|---|---|
| ![10. 객관식](C:/Users/manis/flutter_PJT/memorize_app/design_audit_2026-09-05/12-quiz-question.png) | ![11. 선택 상태](C:/Users/manis/flutter_PJT/memorize_app/design_audit_2026-09-05/13-quiz-selected.png) |

**잘된 점:** 네 선택지가 모두 보이며 누를 영역이 넓다. 선택 후 해당 영역의 배경·테두리가 변하고 정답 확인 버튼이 녹색으로 활성화된다. 제출 전까지 답안을 확정하지 않는다.

**문제:** 상단 설명·통계 패널은 y=263~778로 약 515px를 차지한다. 맞음/틀림 영역까지 거친 뒤 실제 문제는 y=927에서 시작한다. 문제보다 과정 설명을 먼저 읽게 된다. 아직 한 문제도 제출하지 않았는데 `진행률 8%`, `남음 11개`라고 보여 완료 진행률과 현재 문항 위치가 혼동된다. 선택지는 부드러운 그림자가 강하고 선택 상태는 주로 색·테두리로 구분된다.

**수정 방향:** 상단을 `1 / 12`와 간단한 진행 표시로 줄이고 문제를 위로 올린다. 진행률을 완료 응답 기준으로 할지 문항 위치로 할지 명시한다. 선택지에는 A/B/C/D나 radio 표시를 사용하고 선택 체크를 추가한다. 선택지는 평평한 표면·일관된 테두리로 구분하고 굵은 그림자를 줄인다.

**접근성 위험:** 선택 후에도 해당 선택지의 UI 트리 `selected`가 false다. 이것만으로 스크린리더 오류를 확정할 수는 없지만, 선택 상태가 명시적으로 전달되는지 확인해야 한다.

**우선순위/검증:** P1. 문항이 첫 시선 대상이며 선택 상태를 색 없이도 인지한다. 정답/오답 제출과 결과는 사용자 학습 기록에 영향을 주므로 이번에는 실행하지 않았다.

## 12~13. 단어장 — 기본 자료와 내 자료의 우선순위

| 12. 진입 직후 | 13. 아래로 스크롤 |
|---|---|
| ![12. 기본 자료 목록](C:/Users/manis/flutter_PJT/memorize_app/design_audit_2026-09-05/16-wordbooks.png) | ![13. 가져오기와 내 목록](C:/Users/manis/flutter_PJT/memorize_app/design_audit_2026-09-05/17-wordbooks-lower.png) |

**잘된 점:** 기본 자료가 단계별로 있고 가져오기 방법도 구분된다. 고급 기능은 접어두었으며 검색창은 스크롤 후에도 상단에 유지된다.

**문제:** `단어장 관리` 진입 직후 기본 단어장 6개가 먼저 나오고, 가져오기·고급 관리 다음에야 사용자가 가진 단어장이 나온다. 반복된 아이콘, 단계명과 단계 배지, 1000개 수록, 단계별 학습 설명이 한 카드 안에서 공간을 많이 사용한다. `추가`와 `추가됨`도 비슷한 회색 pill로 보여 실행 가능 상태 차이가 약하다.

**수정 방향:** 기본 탭은 내 단어장으로 하고 기본 자료는 `기본 단어장 찾기` 영역으로 분리한다. 카드마다 반복되는 공통 정보는 섹션 설명으로 옮긴다. 추가 가능한 항목은 명시적 버튼, 추가된 항목은 체크와 상태 라벨로 구분한다. Google Sheets와 파일 가져오기는 하나의 추가 흐름에서 고를 수 있게 정리한다.

**접근성/한계:** 추가 상태를 색에만 맡기지 않는다. 기본 자료 추가·가져오기는 실행하지 않았다.

**우선순위/검증:** P1. 재방문 사용자가 첫 화면에서 내 단어장을 찾고, 기본 자료는 필요할 때 발견할 수 있어야 한다.

## 14. 단어장 플랜 — 실제 텍스트 충돌과 버튼 불균형

![14. 플랜과 내 단어장](C:/Users/manis/flutter_PJT/memorize_app/design_audit_2026-09-05/18-wordbook-plan.png)

**잘된 점:** 현재 사용 단어장은 테두리·활성 배지·사용 중 라벨로 구분된다. 편집과 플랜 행동이 노출되어 있다.

**확인된 문제:** `복습 우선 모드 · 새 단어 하루 최대 10개`와 `2%`가 같은 줄 끝에서 붙어 `10개2%`처럼 읽힌다. 두 스크롤 위치에서 같은 문제를 확인했다. 또한 `이 단어장 사용`은 작고 `단어 편집`, `플랜 수정`은 커서 같은 행의 버튼이 서로 다른 규칙으로 보인다. 가장 진한 버튼은 학습 시작이 아니라 플랜 수정이다.

**수정 방향:** 플랜명과 진행률을 다른 줄로 분리하고 설명은 자동 줄바꿈한다. 세 버튼을 무조건 한 줄에 맞추며 글자를 축소하지 말고, 주요 행동 하나와 보조 메뉴로 정리하거나 좁은 폭에서 세로로 배치한다. 목록 카드에서는 핵심 수치만 남기고 자세한 플랜 정보는 상세로 옮긴다.

**접근성:** 시스템 확대·굵게 표시에서 재현된 확정 레이아웃 문제다. 기본 설정만 맞추는 것으로 해결을 완료했다고 판단해서는 안 된다.

**우선순위/검증:** P1 최우선. 현재 조건과 더 좁은 폭에서 플랜 문장·진행률·버튼 라벨이 서로 붙거나 축소되지 않아야 한다.

## 15. 단어 편집 목록 — 읽는 밀도와 편집 행동

![15. 단어 목록](C:/Users/manis/flutter_PJT/memorize_app/design_audit_2026-09-05/19-word-list.png)

**잘된 점:** 단어·대표 뜻·한글 추가 뜻을 읽기 쉽고 관리 메뉴가 일관된 위치에 있다. 전체와 SRS 필터도 제공된다.

**문제:** 1개 단어가 약 409px 높이를 사용해 이 화면에서는 3개와 다음 항목 일부만 보인다. 각 항목의 `새 단어 / 첫 학습 전`이 중복되며 목록을 찾는 속도보다 상태 설명에 공간을 쓴다. 화면 제목은 편집인데 실제 편집은 작은 더보기 메뉴에 있다. 위쪽의 큰 `대표 뜻 일괄 변경`은 매번 필요한 행동은 아니다. 필터 일부가 가로로 보이는 것은 스크롤 가능한 목록이므로 즉시 overflow 버그라고 판단하지 않는다.

**수정 방향:** 기본 목록은 단어·대표 뜻·추가 뜻을 중심으로 조밀하게 하고 상태는 작은 배지 하나로 정리한다. 행 탭 시 상세/편집이라는 규칙을 정하고 더보기는 부가 행동에 사용한다. 일괄 작업은 도구 메뉴나 선택 모드로 옮긴다.

**접근성/한계:** 글자를 강제로 작게 만드는 대신 중복 메타데이터를 줄여 밀도를 개선해야 한다. 키보드·편집 저장·검색 결과 상태는 미검증이다.

**우선순위/검증:** P2. 확대 환경의 가독성을 유지하면서 단어를 비교·찾는 데 필요한 스크롤을 줄인다.

새 시안을 만들 때는 **차분한 종이 느낌을 유지하면서, 장식 깊이를 줄이고 학습 콘텐츠를 크게 드러내는 방향**을 추천한다. 화면마다 모두 흰색으로 바꾸거나 무조건 작은 글자로 바꾸는 방식은 권하지 않는다. 실제 새 디자인 이미지나 구현은 이번 평가 요청에 포함하지 않았다.

## 개선 순서

1. 단어장 플랜의 문장/퍼센트 충돌과 버튼 크기 불균형 수정.
