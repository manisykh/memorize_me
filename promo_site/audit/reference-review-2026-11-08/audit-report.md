# Memorize Me 홈페이지 개선 진단

검토일: 2026-11-08  
비교 대상: Slack 한국어 홈페이지, Toss 홈페이지, Memorize Me 운영 홈페이지

## 종합 판단

현재 홈페이지는 핵심 문구와 기능 구성이 부족한 것이 아니다. 문제는 거의 모든 기능을 긴 휴대폰 스크린샷으로 반복해서 보여주기 때문에 실제 UI 글자가 작아지고, 화면 아래에 빈 공간이 생기며, 설명서처럼 보인다는 점이다.

Slack과 Toss는 기능마다 같은 장치 프레임을 반복하지 않는다. 필요한 UI만 자르고, 선택이나 스크롤에 따라 상태가 바뀌는 모습을 짧게 보여주며, 구역별 배경과 레이아웃 리듬을 바꾼다. Memorize Me도 `스크린샷 나열`에서 `기능별 제품 데모` 중심으로 전환하는 것이 적절하다.

6. `08-memorize-feature.png` — 탭 구조는 좋지만 우측의 긴 휴대폰 화면이 가독성과 밀도를 낮춤

## 단계별 진단

| 단계 | 상태 | 판단 |
|---|---|---|
| Slack 첫 화면 | 양호 | 한 문장과 한 제품 장면에 집중한다. |
| Slack 기능 데모 | 양호 | 사용자의 선택과 결과가 같은 화면에서 연결된다. |
| Toss 첫 화면 | 양호 | 인상은 강하지만 Memorize Me가 그대로 복제하기에는 영상 비중이 크다. |
| Toss 기능 설명 | 양호 | 필요한 기능만 잘라 보여줘 모바일에서도 내용이 읽힌다. |
| Memorize Me 첫 화면 | 부분 개선 필요 | 카피와 CTA는 좋지만 제품 화면이 너무 길고 작다. |
| Memorize Me 학습 방식 | 개선 필요 | 인터랙션 기반은 있으나 장치 프레임과 빈 공간이 실제 기능을 가린다. |

## 권장 개편 방향

### 1. 첫 화면

- 현재 제목 `이미 만든 단어장, 그대로 외우세요.`는 유지한다.
- 긴 홈 화면 대신 상단 핵심 영역만 55~65% 정도 보여준다.
- `단어장 선택 → 오늘 학습 숫자 갱신 → 학습 시작`을 8~12초의 짧은 반복 데모로 만든다.

### 2. 핵심 장점 세 가지

- 모바일에서는 세로 카드 세 개로 배치한다.
- 가져오기: 시트 행이 단어 카드로 바뀌는 모습
- 학습: 카드 뒤집기, 객관식 선택, 스펠링 입력이 순차 전환되는 모습
- 복습: 기억 단계와 다음 복습 수치가 바뀌는 모습
- 이 구역에는 휴대폰 전체 프레임을 사용하지 않는다.

### 3. 학습 방식

- 데스크톱의 왼쪽 탭·오른쪽 데모 구조는 유지할 수 있다.
- 오른쪽에는 선택한 기능에 필요한 카드와 버튼만 확대해서 보여준다.
- 모바일에서는 좌우 스와이프와 탭 선택을 동기화하고, 1:1~4:5 비율 안에서 구성한다.

### 4. 복습과 통계

- 전체 통계 화면 대신 원형 진행률, 오늘·내일 일정, 기억 단계 변화를 조합한다.
- 숫자 변화가 기능의 결과를 설명하도록 짧게 애니메이션한다.

### 5. 선택형 AI

- `단어 → 예문 보강 → 문제 생성 → PDF/HTML 내보내기`를 짧은 스토리보드로 보여준다.
- AI 설정 전체 화면보다 생성 결과와 내보내기 결과를 중심으로 보여준다.

## 모바일 기준

- 별도 모바일 사이트가 아니라 같은 페이지의 반응형 구성을 사용한다.
- 360~430px에서는 모든 비교 카드를 한 열로 쌓는다.
- 제품 데모는 최대 4:5 정도로 제한하고 긴 화면 전체를 노출하지 않는다.
- 화면 밖 애니메이션은 정지하고, 하단 구역은 지연 로딩한다.
- 애니메이션마다 일시정지·다시보기와 `prefers-reduced-motion` 대체 화면을 제공한다.

## 우선순위

### P0

- 첫 화면·학습 방식·복습 구역에서 긴 휴대폰 스크린샷 반복 제거
- 모바일 카드 세로 적층과 제품 데모 비율 수정
- 한 구역에서 한 개의 활성 장면만 강조

### P1

- 가져오기·학습·복습 마이크로 데모 제작
- 탭과 좌우 스와이프 상태 동기화
- 애니메이션 정지와 모션 감소 대응

### P2

- AI 생성·내보내기 스토리보드
- 구역별 정교한 스크롤 전환과 사용자 후기 보강
