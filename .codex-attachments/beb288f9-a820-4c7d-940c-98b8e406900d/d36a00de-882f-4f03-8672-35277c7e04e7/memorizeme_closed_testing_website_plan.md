# Memorize Me 홈페이지 개선 기획서

> 비공개 테스터 모집 및 Google Play 정식 출시 안내
>
> 작성일: 2026-11-26 · 대상: [Memorize Me 공식 홈페이지](https://memorizeme-app.netlify.app/)

## 1. 목적 및 핵심 방향

현재 홈페이지는 단어장 가져오기, 플래시카드, 퀴즈, 복습, AI 학습 기능을 소개하는 공식 제품 홈페이지다. 이 구조를 유지하면서 비공개 테스트 참여로 이어지는 전환 동선을 추가한다. 모집 전용 사이트로 전면 개편하지 않으며, 정식 출시 이후에도 동일한 홈페이지를 활용할 수 있도록 설계한다.

**최종 권장안: 기존 출시 상태 문구 변경 + 메인 CTA 추가 + 별도 테스트 안내 섹션 + 클릭 시 신청 모달 + 출시 상태 통합 관리.**

### 1.1 디자인 원칙

- 기존 메인 카피, 브랜드 색상, 타이포그래피, 여백, 앱 화면 이미지 및 기능 소개를 유지한다.
- CTA는 기존 버튼 디자인을 재사용하며 주 행동과 보조 행동의 시각적 위계를 명확하게 구분한다.
- 자동 팝업, 고정 모집 배너, 과도한 배지, 장식용 그라데이션, 불필요한 애니메이션은 적용하지 않는다.
- 모바일을 우선 고려하고 기존 반응형 레이아웃을 유지한다.
- 개발자 입장의 출시 조건보다 사용자 입장의 사전 체험 가치와 참여 방법을 먼저 전달한다.

## 6. 테스터 신청 모달 및 사용자 흐름

### 6.1 기본 흐름

```text
테스터 신청하기 클릭
 → 신청 모달 열기
 → Google 계정 이메일 입력 및 필수 동의
 → 신청 접수
 → 운영자가 Play Console 테스터 목록에 등록
 → 테스트 참여 링크 이메일 안내
 → 사용자가 링크에서 참여 동의(opt-in)
 → Google Play에서 앱 설치 및 실제 학습
 → 참여 상태 유지 및 의견 전달
 → 정식 출시 안내
```

신청 접수와 Google Play 테스트 참여 시작은 별개다. 신청 완료만으로 참여 기간이 시작된다고 표현하지 않는다.

### 6.2 신청 모달 구성 (게시용 문구)

**제목:** 비공개 테스터 신청

**설명:** 정식 출시 전 Memorize Me를 먼저 경험해 보세요. 신청하신 이메일로 테스트 참여 방법을 안내해 드립니다.

| 입력 항목 | 필수 여부 | 비고 |
|---|---|---|
| Google 계정 이메일 | 필수 | Google Play에서 사용하는 계정. Gmail 주소만으로 제한하지 않음 |
| 주요 사용 목적 | 선택 | 학생 학습 / 자녀 학습 / 교육 및 강의 / 개인 어학 공부 / 기타 |
| 테스트 참여 확인 | 필수 | Android 기기에서 최소 14일 동안 테스트 참여 상태를 유지할 수 있음 |
| 개인정보 수집 및 이용 동의 | 필수 | 실제 처리방침 및 별도 수집·이용 안내와 연결 |
| 정식 출시 알림 수신 | 선택 | 필요한 경우 테스트 안내와 구분해 별도 동의 |

**이메일 도움말:** Google Play에서 사용하는 Google 계정을 입력해 주세요.

**참여 확인 문구:** Android 기기에서 최소 14일 동안 비공개 테스트 참여 상태를 유지하고 앱을 사용해 볼 수 있습니다.

**제출 버튼:** 테스터 신청하기

**개인정보 안내:** 수집 목적, 항목, 보유 기간, 동의 거부 가능 여부 및 문의 방법을 실제 운영 정책에 맞춰 명시한다. 선택 항목은 미동의 상태로 초기화한다. 이름, 전화번호, 생년월일 등 모집에 필요하지 않은 개인정보는 요구하지 않는다. 보호자 동의가 필요한 경우 실제 요건에 맞는 절차를 마련한다.

### 6.3 신청 결과 및 예외 처리

| 상태 | 문구 예시 / 처리 |
|---|---|
| 제출 중 | 신청을 접수하고 있습니다. / 중복 클릭 방지 |
| 접수 성공 | 신청이 접수되었습니다. 테스터 등록 후 입력하신 이메일로 참여 방법을 안내해 드립니다. |
| 이메일 형식 오류 | 올바른 이메일 주소를 입력해 주세요. |
| 필수 동의 누락 | 테스트 참여 조건과 개인정보 수집 안내를 확인해 주세요. |
| 중복 신청 | 중복 저장 및 안내 메일을 방지한다. 공개 화면에서 다른 사람의 신청 여부가 노출되지 않도록 한다. |
| 네트워크 오류 | 신청을 완료하지 못했습니다. 잠시 후 다시 시도해 주세요. / 입력 내용 유지 |
| 모집 마감 | 현재 테스터 모집이 종료되었습니다. 출시 알림을 신청해 주세요. |

접수 성공 메시지는 실제 저장 성공을 확인한 후에만 표시한다. 테스트 링크를 즉시 제공할 수 없는 경우 발송 시점을 확정해서 약속하지 않는다.

### 6.4 모달 UX 및 접근성

- 페이지 첫 방문 시 자동으로 표시하지 않는다.
- 닫기 버튼, Escape 키, 포커스 관리 및 닫은 후 원래 버튼으로 포커스 복귀를 지원한다.
- 모바일에서는 화면 내 스크롤이 가능한 모달 또는 전체 화면에 가까운 신청 화면을 사용한다.
- 입력 오류는 해당 필드 가까이에 표시하고 키보드 및 스크린리더 사용을 지원한다.
- 서버에서 이메일 형식, 필수 항목, 중복 요청 및 스팸을 검증한다.

## 7. Google Play 출시 절차 (운영자용)

2023년 11월 13일 이후 생성된 개인 개발자 계정에 적용되는 Google Play의 테스트 요구사항을 기준으로 작성한다. 실제 계정 유형 및 Play Console 대시보드에서 적용 조건을 확인한다.

1. 비공개 테스트 트랙 및 테스트용 릴리스를 준비한다.
2. 신청 이메일을 Play Console 이메일 목록 또는 Google Groups에 등록한다.
3. 테스트 참여 링크를 발송하고, 테스터가 올바른 계정으로 참여에 동의한 뒤 앱을 설치하도록 안내한다.
4. 최소 12명의 테스터가 14일 연속 참여 상태를 유지해야 하는 적용 조건을 충족한다. 중간에 이탈하면 해당 테스터의 연속 참여 기간이 끊어진다.
5. 실제 기능 사용, 오류 제보, 개선 요청을 수집하고 수정 내용을 기록한다. 단순 참여 인원 확보만으로 승인이 보장되지 않는다.
6. 조건 충족 후 Play Console에서 프로덕션 액세스를 신청한다. 테스트 진행 방식, 피드백, 개선 내용 및 출시 준비 상황을 설명한다.
7. 승인 후 프로덕션 릴리스를 제출하고 출시 심사 및 배포 절차를 진행한다.
8. 실제 스토어 다운로드 가능 여부를 확인한 뒤 홈페이지의 출시 상태와 CTA를 변경한다.

프로덕션 액세스 심사에서 추가 테스트를 요구할 수 있다. 공개 테스트는 필수 경로가 아니며, 비공개 테스트 종료일이 정식 출시일을 의미하지 않는다.

**운영 권장사항 (Google 필수 조건 아님):** 이탈에 대비해 적용 최소 인원보다 여유 있게 모집하고, 실제 학습 시나리오를 안내한다. 예를 들어 최초 목표를 15~20명으로 잡되 운영 상황에 따라 조정한다.

테스트 시나리오 예시: 기본 단어장 학습, Google Sheets/CSV/XLSX 가져오기, 플래시카드, 객관식·스펠링 퀴즈, 오답 확인, 복습, 필요한 경우 AI 기능 연결. 기존 의견 게시판과 문의 채널을 활용해 기기/앱 버전/재현 절차/개선 의견을 수집한다. API 키 등 민감 정보는 받지 않는다.

## 8. 참여 혜택

### 8.1 확정 전 기본 문구

- 정식 출시 전 앱 사전 체험
- 나만의 단어장을 활용한 학습 경험
- 오류 및 개선 의견 전달을 통한 앱 개선 참여

### 8.2 조건부 혜택 (확정 시에만 게시)

현재 홈페이지에는 초기 출시 혜택 기간에 다운로드한 사용자에게 주요 학습 기능을 평생 무료로 제공할 계획이 명시되어 있다. 그러나 비공개 테스터가 자동으로 해당 혜택을 받는지는 확정되지 않았다.

비공개 테스터에게도 동일한 혜택을 제공할 경우 다음 문구를 사용할 수 있다.

> 초기 테스터 특별 혜택: 정식 출시 후에도 주요 학습 기능을 평생 무료로 이용할 수 있습니다.

게시 전 확인 사항: 적용 기능 범위, 혜택 대상, 참여 충족 조건, 테스트 계정과 정식 출시 권한의 연결 방법, 재설치/기기 변경 시 복원, AI API 제공업체 비용의 별도 적용 여부. 기존 출시 혜택과 충돌하지 않도록 정책 및 앱 권한 로직을 먼저 확정하고 검증한다. 확정 전에는 해당 문구를 표시하지 않는다.

## 10. 상단 메뉴, 하단 CTA, 푸터

- 상단 메뉴: `테스터 모집`을 추가하여 `#closed-testing`으로 이동. 기존 내비게이션은 유지한다. 모바일 메뉴에도 동일하게 반영한다.
- 하단 기존 카피 `이미 정리한 단어장으로, 오늘의 학습을 준비하세요.`는 유지한다.
- 하단 설명 변경: `정식 출시 전에 먼저 경험하거나, 출시 알림을 받아보세요.`
- 하단 Primary CTA: `테스터 신청하기` → 신청 모달.
- 하단 Secondary CTA: `출시 알림 받기` → 기존 알림 신청 흐름 또는 별도 이메일 수신 동의 양식.
- 푸터의 `Google Play 출시 준비 중`은 `Android · 비공개 테스터 모집 중`으로 변경한다.
- 기존 의견 게시판, AI API 연결 가이드, 개인정보 처리방침, 계정 삭제 안내, 문의 채널은 유지한다.

## 11. 출시 상태별 공통 설정

출시 관련 텍스트와 버튼을 개별 컴포넌트에 하드코딩하지 않고 단일 설정에서 관리한다. 기존 홈페이지 기술 스택 및 구조를 확인한 후 적합한 파일에 통합한다.

| 상태 키 | 표시 문구 | 메인 CTA | 로드맵 단계 |
|---|---|---|---|
| `recruiting` | Android · 비공개 테스터 모집 중 | 테스터 신청하기 | 1 |
| `testing` | Android · 비공개 테스트 진행 중 | 출시 알림 받기 | 2 |
| `reviewing` | Google Play 출시 승인 및 심사 진행 중 | 출시 알림 받기 | 3 |
| `released` | Google Play 정식 출시 | Google Play에서 다운로드 | 4 |

`testing` 상태에서도 추가 모집이 필요한 경우 신청 CTA를 활성화할 수 있도록 상태와 모집 여부를 분리한다. `released`는 스토어에서 다운로드 가능함을 확인한 후에만 설정한다.

설정 예시 (기존 프레임워크에 맞춰 변경):

```json
{
  "releaseStatus": "recruiting",
  "acceptingTesters": true,
  "minimumParticipationDays": 14,
  "testerBenefitConfirmed": false,
  "playStoreUrl": null,
  "feedbackUrl": null
}
```

- `releaseStatus`: Hero, 메뉴, 안내 로드맵, FAQ 상태 문구, 하단 CTA, 푸터의 공통 기준.
- `acceptingTesters`: 모집 가능 여부. 신청 모달과 서버의 접수 허용 상태도 함께 제어.
- `testerBenefitConfirmed`: 확정 혜택 노출 여부. 기본값 `false`.
- `playStoreUrl`: 실제 스토어 주소 확인 후 설정. 미설정 상태에서 다운로드 CTA를 표시하지 않음.
- `feedbackUrl`: 기존 의견 게시판 URL을 재사용하거나 설정에서 연결.

정식 출시 후 테스트 모집 안내는 일반적인 출시 안내 또는 과거 테스트 소개로 정리한다. 모든 모집 CTA를 다운로드 CTA와 혼동되지 않게 변경한다.

## 12. 신청 데이터 및 운영 구현

Netlify 배포 환경을 고려하면 초기 버전에서는 Netlify Forms를 검토할 수 있다. 다만 현재 프로젝트의 프레임워크, 폼 인식 방식, 요금제 및 기존 신청 백엔드를 확인하고, 이미 동작하는 수집 시스템이 있다면 이를 우선 재사용한다.

### 12.1 데이터 및 관리 항목

| 항목 | 내용 |
|---|---|
| `email` | 신청한 Google 계정 이메일 |
| `usePurpose` | 선택 입력: 주요 사용 목적 |
| `participationConfirmed` | 참여 조건 확인 |
| `privacyConsent` | 필수 개인정보 동의 여부 |
| `privacyNoticeVersion` | 동의한 안내문 버전 |
| `releaseNotificationConsent` | 선택적 출시 알림 동의 |
| `submittedAt` | 서버에서 기록한 신청 접수 시각 |
| `status` | 운영 상태 (접수/등록/안내 발송 등) |

실제 Google Play 참여 여부 및 연속 참여 기간은 신청 데이터만으로 추정하지 않고 Play Console에서 확인 가능한 정보로 관리한다.

### 12.2 운영 방식

초기에는 신청 접수 → 관리자 확인 → Play Console 등록 → 참여 링크 이메일 발송 순서로 수동 운영한다. 수집 정보는 접근 권한을 제한하고 실제 목적에 필요한 기간만 보관한다. 알림 발송 자동화는 접수 및 개인정보 처리 방식이 확정된 후 검토한다.

테스터 이메일 목록, 내부 운영 상태, 개인정보는 홈페이지 클라이언트 코드나 공개 API에 노출하지 않는다. 링크 발송에 필요한 비밀 키는 서버 측 환경에서만 관리한다.

## 13. 구현 우선순위

| 우선순위 | 작업 |
|---|---|
| P0 (필수) | Hero 출시 상태 및 CTA, 공통 출시 상태 설정, 신청 모달/접수 처리, 실제 개인정보 안내, 신규 테스트 안내 및 로드맵, 하단 CTA와 푸터 일관성 |
| P1 (권장) | 상단 메뉴, 테스트 FAQ, 신청 상태 오류 처리 및 접근성 점검, 운영자 신청 데이터 관리, 기존 의견 게시판 연동 |
| P2 (선택) | 동의 기반 알림 자동화, 개인정보를 포함하지 않는 CTA 전환 분석, 테스터 특별 혜택 표시 및 앱 권한 연동 |

분석을 적용한다면 `tester_cta_click`, `tester_form_open`, `tester_submit_success` 등의 이벤트를 고려할 수 있다. 이메일 등 개인정보를 분석 이벤트에 포함하지 않는다.

- [ ] FAQ, 하단 CTA, 푸터 상태가 Hero와 일치한다.
- [ ] 비공개 테스트 신청과 실제 opt-in이 구분되어 안내된다.

- [ ] 기존 AI 연결 가이드, 의견 게시판, 정책 링크가 정상 동작한다.
